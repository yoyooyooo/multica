## Capability decisions

| Capability | Decision | Contract and implementation |
| --- | --- | --- |
| Native GitHub/VCS links, status categories, parent notifications | upstream | Keep v0.5.0 behavior, including cancellation warnings and fail-closed custom-status resolution. |
| External PR authority | keep | Explicit AGS identity, service-token authentication, strict payload validation, immutable merged facts, idempotency and durable reconciliation remain required. Upstream has no equivalent authority endpoint. |
| External completion integration | reimplement | Open-PR queries follow removal of `reference_only`; all GitHub, VCS and AGS open/draft links block completion. Stable comment identity reuses the current upstream comment builder, status resolver and trigger paths. |
| AGS current execution context v2 | keep | Live task-token binding, token/task locking, server-only hash header, credential-free closed v2 response, and terminal-task rejection remain required by AGS. |
| Independent migration stream and readiness | keep | Use the upstream runner with a separate ledger and advisory lock. Preserve already-applied fork 001 byte-for-byte. |
| Offline font assets | keep | Fontsource assets retain Latin normal/italic faces and locale-specific CJK fallback without Google Fonts build-time fetches. |
| Fork release/build/deploy boundary | keep | Additive image/CLI transactions and immutable target receipts. Include upstream's new maintenance executable in the backend image. |
| Legacy execution-id schema and fork patch queue | retire | Neither is reintroduced. Historical manifests are evidence, not runtime authority. |

The existing `001_external_pr_authority` migration predates the current no-new-FK
and concurrent-index rules. It is retained unchanged because both targets have
applied it; this generation adds no migration, foreign key, trigger, or index.
The legacy trigger-based cleanup remains an explicit compatibility surface and
is covered by migration/deletion tests, not represented as a new design pattern.

## Preflight

At initial preflight both target databases had zero queued/executing tasks and
zero queued/running autopilots. Both daemons reported zero active tasks and
`v0.4.37-31-g1ac10890c`. These observations are not a cutover authorization:
idle checks must run again immediately before switching each target.

Local Git transport through Sparkle's default port 7890 matched an earlier
`github.com -> Grok-Bot` rule, ahead of `Exit-GitHub`, and stalled. A temporary
SSH SOCKS tunnel through imile-win completed the fetch; it was stopped after
Sparkle's existing `127.0.0.1:17993` listener was independently verified. Further
Git operations use a per-command proxy override; shared routing was not changed.
