## Rollback and retained artifacts

Keep old image IDs, raw CLI bytes, profile configs, daemon identity, original resolved Compose, frozen dumps, independent restore volumes, and transaction receipts. Old daemon directory names are not reliable version evidence; actual executable bytes and metadata were recorded.

Database rollback means: stop applications, restore the pre-switch dump into a fresh database, verify it, retain the upgraded database under a unique archive name, then switch database names and start the original application images. On Win, block database connections explicitly from the maintenance database during the rename boundary. `pg_restore --clean` into an upgraded database is not a complete rollback. Do not delete the quarantine archive or rewrite migration ledger entries.

Each CLI rollback restores its previous profile config and command and restarts that same profile. Distinct profiles keep their own server, UUID, device name, and previous executable. A task legitimately claimed after restart is recorded, not cancelled just to produce a zero counter.
